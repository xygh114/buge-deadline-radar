## 2. 优先级：紧急 × 重要（艾森豪威尔矩阵）

```
优先级 = round(100 × (60% × 紧急度 + 40% × 重要度))

紧急度 = 60% × 时间余量紧迫 + 40% × 截止临近
  时间余量紧迫 = 剩余工时 ≥ 剩余时间 ? 1 : e^(−(剩余时间 − 剩余工时)/60)
  截止临近     = 1 / (1 + 剩余小时 / 36)      // 逾期直接记 1

重要度 = 40% × 成绩占比 + 20% × 课程学分 + 20% × 绩点压力
       + 12% × 关联周/月目标 + 8% × 手动重要程度
  成绩占比 = min(占总评% / 40, 1)
  课程学分 = min(课程学分 / 4, 1)
  绩点压力 = clamp((目标绩点 − 当前绩点) / (0.15 × 绩点制), 0, 1) × 成绩占比
```

四象限：紧急度 ≥ 0.55 且重要度 ≥ 0.55 → 「马上做」；否则按重要度高 / 紧急度高 / 都不高
落到「计划做」「顺手做」「有空做」。界面上每个任务都能看到它落在哪一档，以及为什么。

## 3. 排程：先扣时间，再按优先级塞块

- **先扣固定时间**：12:00–13:30 午饭午休、18:00–19:00 晚饭、23:00 后不排；社团/例会/家调整段扣掉。
- **每天预算**：默认 3 小时（1–8 小时可调），周末 +1 小时、晚起 45 分钟；排满就停。
- **45 分钟一块、块间 10 分钟**；高难度任务（论文/实验/考试/展示）优先上午和晚间，碎片任务放午后低谷。
- **截止缓冲**：按重要度留 0.5–3.5 小时缓冲；长任务往前摊开，短任务尽量连着做完，不堆到截止前一晚。
- **重要不紧急**：周/月目标每天固定 45 分钟（0–120 可调），日目标每天一块；目标进度可由关联任务自动同步。
- **排不下不硬塞**：计划页明确列出「还差多少小时」，建议调高预算、降低预估，或砍掉「不紧急不重要」。

## 4. 数据模型

```js
task     = { id, title, course, platform, type, dueAt, weight, credits, importance,
             goalId, estHours, progress, status, note }
goal     = { id, title, scope: 'day'|'week'|'month', targetHours, progress,
             importance, deadline, course }
activity = { id, title, day: 1..7, start: 'HH:MM', end: 'HH:MM',
             repeat: 'weekly'|'once', date, place }
settings = { dailyHours, weekendBonus, wake, sleep, goalMinutes,
             gpaCurrent, gpaTarget, gpaScale, ...旧字段 }
```

全部存在原来的 `localStorage` 键 `buge.deadline.v1` 里；旧数据加载时会自动补默认字段，不需要迁移脚本。

## 5. 怎么验

```bash
cd buge
node tests/parser.test.js   # 27 / 27：通知解析没有回归
node tests/plan.test.js     # 164 / 164：排程硬约束、四象限、目标/社团/绩点/预算
node tests/e2e.mjs          # 44 / 44：真实 Edge，含逐天切换、目标与社团新增
```

`tests/plan.test.js` 的硬约束包括：块不跨午饭/晚饭、不超过 45 分钟、23:00 前结束、
不与社团重叠、不超每日预算、时间轴有序、同样输入结果确定。

## 6. 已知取舍

- 没有接学校课表，课程和社团都按「固定安排」手动录入。
- 绩点只衡量目标差，不换算每门课的具体绩点公式。
- 日目标建议 0.5–1 小时；超过「每天留给目标」的分钟数时，会按上限截断。
- 排程是启发式而非最优解：优先保证「可解释、每天能执行」，不追求数学上的全局最优。
